## 1. Technical Context

<!-- 
  Identify technical components, libraries, and patterns. 
  Mark unknowns as [NEEDS CLARIFICATION].
-->

**Components:**
- **Entry Point**: `src/main.py` - Orchestrates the application loop and initializes the core manager.
- **Model**: `src/model/task.py` - Defines the `Task` dataclass (Entity).
- **Service**: `src/service/todo_manager.py` - Implements business logic (CRUD operations) and in-memory state management.
- **UI**: `src/ui/cli.py` - Handles user input/output, menu display, and error formatting.

**Libraries:**
- **Standard Library**: `dataclasses`, `typing`, `enum`, `sys` (for exit).
- **Environment**: `uv` for dependency management (though minimal deps required).

**Patterns:**
- **Repository/Service Pattern**: `TodoManager` acts as the service layer, abstracting the "database" (list) from the UI.
- **Singleton (Implicit)**: A single instance of `TodoManager` passed to the UI ensures consistent state.
- **Command Loop**: Infinite `while True` loop in `main.py` breaking on user exit command.

## 3. Phase 0: Research & Decisions

<!-- 
  Identify design decisions and resolve [NEEDS CLARIFICATION] items.
  Output: research.md
-->

**Key Decisions:**
- **Data Structure**: Python `dataclass` is chosen over `pydantic` for Phase I to minimize dependencies as per strict constraints, while still offering type safety.
- **ID Generation**: Simple auto-incrementing integer (max_id + 1) managed by `TodoManager`.
- **UI Framework**: Pure `input()`/`print()` chosen. `rich`/`typer` avoided to strictly adhere to "minimize dependencies" unless formatting becomes complex (not the case here).

**Clarification Status:**
- All requirements are clear. No external research needed for standard Python in-memory lists.
